# Занятие 10. Порты и сокеты

## Главное своими словами
Служба может работать, но не принимать подключения: слушать не тот порт, только адрес 127.0.0.1 или не открыть порт вовсе. Чтобы это увидеть, смотрю, какая программа какой порт и на каком адресе слушает (ss), и проверяю ответ через curl.

## Основное
- IP — адрес здания, порт — номер кабинета, сокет — адрес:порт программы
- Порты ниже 1024 открывает только root; порт 0 — «система, дай любой свободный»
- 127.0.0.1 — только изнутри, 0.0.0.0 — доступно снаружи; доступ определяет адрес, а не номер порта
- База данных должна слушать 127.0.0.1
- Один порт — одна программа, иначе Address already in use

## curl
- -I — заголовки, -v — подробно, -w "%{http_code}" — только код
- Код 7 — не удалось подключиться; на HTTP 404 curl возвращает 0 — для проверок нужен -w или -f
- Connection refused — никто не слушает; timed out — обычно файрвол

## Алгоритм диагностики
status → журнал → ss (порт и адрес) → curl изнутри → curl снаружи → файрвол и DNS

## Что я сделал на практике
- **Учебный сервер Python.** Запустил `python3 -m http.server 8000` и открыл страницу в браузере Windows. В журнале сервера появился запрос браузера и ошибка 404 на /favicon.ico — браузер сам просит иконку сайта. Такую же строку я видел раньше в учебном access.log.
- **0.0.0.0 и 127.0.0.1.** Когда сервер слушал 0.0.0.0, он отвечал и по localhost, и по сетевому адресу (hostname -I). После `--bind 127.0.0.1` по localhost ответ 200, а по сетевому адресу — `Couldn't connect to server` (код 7). Вывод: доступ определяется адресом, на котором слушает служба.
- **Конфликт портов.** Запустил второй сервер на занятый порт — `OSError: [Errno 98] Address already in use`. Через `sudo ss -tlnp` нашёл, что порт держит python3 с PID 20032.
- **Инцидент webdemo.** Задача: сайт на порту 8080 по сетевому адресу. status и журнал ошибок не показали, служба active. ss показал `127.0.0.1:8081`. Нашёл две причины: не тот порт и только локальный адрес. Исправил юнит на 8080 без --bind.
- **Исправление.** После cp и daemon-reload ss всё ещё показывал 8081, enable --now тоже не помог. Только restart применил новые параметры: daemon-reload перечитывает файл, но не перезапускает работающий процесс.

## Что стало открытием
- Доступ снаружи определяется адресом, на котором служба слушает (0.0.0.0 или 127.0.0.1), а не номером порта
- На одном адресе один порт может занять только одна программа
- status может показывать «всё хорошо», а правду о порте и адресе показывает только ss
- curl возвращает код 0 даже на ответ 404
