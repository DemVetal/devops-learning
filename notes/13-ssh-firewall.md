# Занятие 13. Безопасный доступ: SSH, агент ключей, файрвол

## Главное своими словами
Главная дверь в сервер — SSH, в неё постоянно стучатся боты. Защита: вход только по ключу, запрет входа root, файрвол, который открывает только нужные порты. ssh-agent и keychain позволяют вводить passphrase один раз, а не на каждое подключение.

## Вход по ключу и агент
- Публичный ключ на сервере в authorized_keys, приватный остаётся у меня и по сети не передаётся
- ssh-agent хранит разблокированный ключ; keychain делает агента общим для всех вкладок
- Права ~/.ssh 700, ключи 600 — иначе сервер отказывает в ключе

## Защита SSH-сервера
- Свой файл 00-hardening.conf в sshd_config.d: PasswordAuthentication no, PermitRootLogin no
- Побеждает первое значение — номер 00, проверка через sshd -T
- sshd -t перед применением; новый сеанс для проверки, старый не закрывать

## Файрвол
- ufw: deny incoming, allow outgoing, открыть OpenSSH и нужные порты, потом enable
- Сначала SSH — потом enable
- refused — никто не слушает, timed out — файрвол

## Что я сделал на практике
- **ssh-agent и keychain.** Без агента SSH_AUTH_SOCK пустая. Запустил агента вручную — passphrase больше не спрашивали, но новая вкладка агента не видела. Поставил keychain: passphrase один раз после запуска WSL, все вкладки работают.
- **Свой SSH-сервер.** Поставил openssh-server, вошёл по паролю (Accepted password), затем через ssh-copy-id по ключу (Accepted publickey). Поставил chmod 777 на ~/.ssh — сервер отказал в ключе (bad ownership or modes) и предложил пароль.
- **Защита.** Создал 00-hardening.conf, проверил sshd -T: пароли и root отключены. Вход по паролю и под root — Permission denied (publickey), в журнале — [preauth].
- **Файрвол.** ufw не было в WSL — установил. Открыл OpenSSH и 80. Из Windows порт 80 отвечал, 8080 — timed out, хотя webdemo работал. Открыл и закрыл 8080, увидел блокировку в журнале ядра (SRC, DST, DPT).

## Что стало открытием
- Вход по ключу безопаснее: приватный ключ никогда не уходит по сети
- Неправильные права на ~/.ssh при отключённых паролях = потеря доступа к серверу
- На VPS файл 50-cloud-init.conf может незаметно оставить пароли включёнными
- По виду ошибки (refused или timed out) сразу понятно, где искать: служба или файрвол
