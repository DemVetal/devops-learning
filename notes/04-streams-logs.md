# Занятие 4. Потоки, конвейер и обработка логов

## Главное своими словами
У каждой программы есть отдельные каналы (потоки) для ввода, результата и ошибок. Их можно направлять на экран, в файл или передавать другой команде. С помощью конвейера можно собрать одну команду из нескольких маленьких и, например, за одну строку проанализировать лог сайта: найти самые активные IP, ошибки, подозрительные запросы. Это ежедневная работа администратора.

## Три потока
- stdin (0) — ввод. Обычно клавиатура. Если команде не указать файл, она ждёт ввода с клавиатуры (выход — Ctrl+C)
- stdout (1) — вывод данных, результат работы
- stderr (2) — сообщения об ошибках
- По умолчанию stdout и stderr оба идут на экран, поэтому их не видно по отдельности

## Перенаправление
- `>` — записать вывод в файл. Опасен тем, что молча стирает всё, что было в файле
- `>>` — дописать в конец файла. При повторном запуске данные задублируются
- `2>` — записать ошибки в файл; `2>/dev/null` — выбросить ошибки (/dev/null — «чёрная дыра»)
- `> файл 2>&1` — отправить и вывод, и ошибки в один файл
- `>` — для свежих отчётов, `>>` — для логов

## Конвейер
- `команда1 | команда2` — вывод левой команды становится вводом правой
- По конвейеру идёт только stdout. Ошибки всё равно летят на экран
- Передаётся ВЫВОД команды, а не файл: `ls -l файл | grep` ищет в строке описания файла, а не в его содержимом

## Инструменты
- grep: показывает только строки, в которых есть нужный текст (фильтр). `-i` — без учёта регистра, `-v` — строки БЕЗ текста, `-c` — количество, `-n` — номера строк
- cut: вырезает колонку из строки. `-d` — разделитель, `-f` — номер колонки. Сбивается, если пробелов несколько подряд
- sort и uniq: сортировка и объединение одинаковых. uniq склеивает только СОСЕДНИЕ строки, поэтому сначала всегда sort. Без sort одно значение посчитается несколькими кусками
- `sort -n` — сортировать как числа, `-r` — в обратном порядке
- awk: это умный cut. Колонки (поля) нумеруются `$1`, `$2`..., `$NF` — последняя, `$0` — вся строка. Разделитель по умолчанию — любое количество пробелов. Можно выводить нужные колонки и фильтровать по условию. Пример: `awk '$3 == "Город" {print $1}' файл` — выведет первую колонку тех строк, где в третьей колонке «Город»
- В awk: числа без кавычек (`$2 > 30`), текст в кавычках (`$3 == "Киев"`); сравнение — `==`; программа всегда в одинарных кавычках
- Рецепт «топ»: `... | sort | uniq -c | sort -nr | head` — отсортирует строки по алфавиту, соединит одинаковые и посчитает их, отсортирует от большего к меньшему и покажет первые 10

## Что я сделал на практике
- **Анализ лога сайта.** Разобрал access.log с помощью awk и рецепта «топ».
  - Самый активный IP (9 запросов из 21) оказался скриптом (python-requests) — сканером уязвимостей. Он перебирал типичные адреса: админки WordPress и phpMyAdmin, `/.env` и `/config.php.bak` — файлы, где могут лежать пароли. Все ответы — 404, то есть ничего не нашёл.
  - Почти все ошибки 404 — от сканера, а не от посетителей. Вывод: число без контекста — ещё не вывод, нужно смотреть, кто и что запрашивал.
  - Страница оформления заказа `/order.php` дважды вернула ошибку 500 одному и тому же клиенту, успех — только с третьей попытки. Ошибка плавающая, сайт теряет заказы.
  - Рекомендации: срочно проверить лог ошибок (error.log, лог PHP) за время ошибок 500; убедиться, что в папке сайта нет `.env` и `.bak`-файлов; при повторных сканированиях — заблокировать IP.
  - Главный урок: резервные копии конфигов и файлы с секретами никогда не должны лежать в папке, которую отдаёт веб-сервер.

## Что стало открытием
- Насколько гибко можно пользоваться командами и как они все взаимосвязаны: маленькие команды через конвейер складываются в мощный инструмент
- Сканеры уязвимостей приходят на любой публичный сайт постоянно — это фон интернета
- В /etc/passwd есть пользователь nobody (UID 65534) — фильтр «UID >= 1000» его захватывает, результат всегда нужно проверять глазами
