# Занятие 7. Bash-скрипты

## Главное своими словами
Скрипт — это файл с командами, которые выполняются по порядку. Один раз написал — дальше запускаешь одной командой или по расписанию. Это основа автоматизации, на которой строится весь DevOps: CI/CD, Ansible, Docker — развитие той же идеи.

## Основа
- Первая строка `#!/bin/bash`, комментарии через `#`
- Переменные в скриптах всегда в двойных кавычках: без них Bash разрезает значение по пробелам (`touch $FILE` создал два файла вместо одного)
- `set -euo pipefail` в начале скрипта: остановка при ошибке, при опечатке в переменной, при ошибке в конвейере. Лучше упасть с понятной ошибкой, чем «успешно» сделать вред
- `set -e` не срабатывает внутри условия `if`

## Код возврата
- Каждая команда возвращает число: 0 — успех, другое — ошибка или «нет». Хранится в `$?` (только для последней команды)
- grep: 0 — нашёл, 1 — не нашёл, 2 — ошибка. Не любой ненулевой код — авария
- Свой скрипт возвращает код через `exit`, функция — через `return`. Коды выбирает автор и описывает в комментарии
- По кодам скрипты, CI/CD и мониторинг понимают, что именно пошло не так

## Условия
- `if` проверяет код возврата команды: 0 — «да», иначе — «нет»
- Проверки `[ ]`: `-f` файл, `-d` папка, `-z` пустая переменная, `!` — отрицание; числа: `-gt -lt -ge -le -eq -ne`
- Пробелы внутри `[ ]` обязательны, потому что `[` — это команда
- `&&` — выполнить, если успешно; `||` — если не удалось

## Циклы и функции
- `for X in список` — для каждого элемента; `while read -r line ... < файл` — для каждой строки файла
- `continue` — к следующему кругу; `$((A + 1))` — арифметика
- Функции — чтобы не повторять код; `local` — переменные только внутри функции; `return` — выход из функции без остановки скрипта
- Многострочные команды в терминале: Enter и приглашение `>`, или одной строкой через `;`

## Мои скрипты (scripts/)
- `sysinfo.sh` — сводка о системе: дата, пользователь, память, диск, время работы
- `check_path.sh` — определяет, что по указанному пути: файл, папка или ничего; разные коды возврата
- `backup.sh` — архивы папок с датой, функция с проверкой, счётчик ошибок, ротация старше 7 дней
- `check_disk.sh` — проверка заполненности дисков с порогом, значение по умолчанию, проверка аргумента, коды 0/1/2, журнал через tee

## Что я сделал на практике
- **backup.sh.** Функция делает бэкап одной папки; если папки нет — сообщает и возвращает ошибку, а цикл продолжает бэкап остальных. Проверил содержимое архива через `tar -t`. Добавил ротацию через `find -mtime +7 -delete` (сначала проверил без `-delete`).
- **check_disk.sh.** При первом запуске пропустил пробел в `[ ]`: проверка сломалась, и скрипт сообщил «все диски OK, проблем 0», хотя диск F: был заполнен на 93%. Ошибка была видна в выводе (`[: missing ']'`). Исправил и протестировал все случаи: порог 80 (2 проблемы, код 1), 95 (всё OK, код 0), abc (код 2), 1 (все диски, код 1). Вывод: проверку нужно испытывать на случае, когда она обязана сработать.
- Скрипт нашёл реальную проблему: диск F: заполнился с 82% до 93% за неделю.

## Что стало открытием
- Сломанная проверка может молча говорить «всё хорошо» — это опаснее, чем явная ошибка
- Ненулевой код не всегда означает аварию (grep «не нашёл»)
- Bash сам переводит многострочную команду в одну строку (стрелка ↑)
- Git сохраняет право на запуск файла (100755)
