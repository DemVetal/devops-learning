# Занятие 5. Архивы, переменные окружения и PATH

## Главное своими словами
 Научился упаковывать папки в архивы и восстанавливать их — это основа бэкапов. Понял, как программы получают настройки через переменные окружения, и как Linux находит команды через PATH.

## Архивы
- tar и gzip — в чём разница: tar - это упаковка в архив, а gzip это процесс сжатия. Вместе — .tar.gz.
- Упаковать: tar -czf архив.tar.gz папка; посмотреть: tar -tzf архив.tar.gz; распаковать: tar -xzf архив.tar.gz (в другое место — -C папка/). Буква f всегда последняя.
- Опасности: tar -x молча перезаписывает файлы в текущей папке; gzip заменяет оригинал сжатым файлом. 
- tar сохраняет права, владельца и даты.
- Главное правило бэкапов: бэкап, из которого не пробовали восстановиться, — не бэкап.

## Переменные окружения
- Что такое переменная, как создать и прочитать: Переменная — коробка с именем: ИМЯ="значение" (без пробелов вокруг =), прочитать: echo $ИМЯ.
- Чем обычная переменная отличается от export: Обычная переменная видна только в текущем терминале. export делает её переменной окружения — её получают запущенные из терминала программы (копию, и только «вниз»).
- Двойные и одинарные кавычки: "$HOME" — значение подставится, '$HOME' — останется текстом.
- Как сделать переменную постоянной: Чтобы переменная была постоянной — записать в ~/.bashrc (сначала бэкап, дописывать через >>) и выполнить source ~/.bashrc.
- Опечатка в имени переменной даёт пустоту без ошибки — это опасно.
- Зачем это в DevOps:В DevOps так передают настройки приложениям, Docker и CI/CD (формат как в .env).
- Пароли нельзя вводить в командах — они остаются в history.

## PATH
- Как Bash находит команду: В PATH — список папок. Bash ищет команду по ним по порядку и запускает первую найденную.
- Почему ./ для своих скриптов: Текущей папки нет в PATH ради безопасности, поэтому свои скрипты запускаются через ./.
- which и type — в чём разница; три вида команд: which показывает, где лежит файл программы; type — что это: программа, встроенная команда (cd) или псевдоним (ll).
- Как правильно добавить папку в PATH и как нельзя: Добавлять папку только так: export PATH="$HOME/bin:$PATH". Без :$PATH пропадут все команды.

## Что я сделал на практике

Проверил, что всё на месте, включая .env с правами 600. Восстановил ещё раз в отдельную папку restore-test. Сделал бэкап с датой в имени: server-2026-10-27.tar.gz.
- **Своя команда hello.** Создал ~/bin, скопировал туда скрипт как hello, добавил ~/bin в PATH через ~/.bashrc. Теперь hello запускается из любой папки.
