# Занятие 3. Пользователи, группы и права доступа

## Главное своими словами
Пользователи и права в Linux для того что бы можно было каждому пользователю выдать только столько прав каких ему будет достаточно для работы. Получается минимум привелегий


## Пользователи
- Где хранятся: /etc/passwd
- Формат строки /etc/passwd: login : пароль : UID : GID : комментарий : домашняя папка : оболочка (shell)
- UID 0 — root, UID < 1000 — системные пользователи, UID ≥ 1000 — пользователи
- nologin — под этим UID нельзя зайти. Системный пользователь
- Где пароли и почему закрыты: /etc/shadow там хранятсе хэши паролей

## Группы
- Зачем: что бы выдавать права сразу нескольким пользователям
- Основная и дополнительные: Основная обычно совпадает с пользователем, его личная. А дополнительная это уже как раз выдаёт право пользоваться другими например sudo
- Добавить в группу: `sudo usermod -aG группа пользователь` — почему именно так: `-aG ` добавляет группу к уже существующим у пользователя
- Когда применяется: когда нужно открыть группу пользователю

## Права доступа
- Строка прав: -,d,l - тип, rwx - владелец,  rwx - группа, rwx - все остальные
- Порядок проверки: сначала владелец, потом группа, потом уже все остальные
- r, w, x для файла: читать, изменять, запускать как программу
- r, w, x для папки: видеть список, создавать и изменять файлы внутри, заходить в папку
- Цифры: r=4, w=2, x=1; 644 — rw-r--r--, 600 — rw-------, 755 — rwxr-xr-x, 700 — rwx------
- root и права: root имеет доступ ко всем сразу правам

## Изменение прав
- chmod буквами: chmod u+x файл - добавить доступ к запуску
- chmod цифрами: chmod 700 - Закрыть всем доступ кром владельца и root
- chown / chgrp: sudo chown www-data:www-data hello.sh - может выполнить только root
- Никогда не делаю: никогда не открывать доступ всем пользователям ко всему

## Особые биты
- sticky bit (t): это значит все новые файлы в этой папке получают права на изменения только этого юзера
- setgid (s): Специальный бит setgid на папке. С ним все новые файлы внутри автоматически получают группу папки.

## Что я сделал на практике
- Я его не мог запустить так как небыло прав x, команда `chmod u+x hello.sh` решение.
- **Секретный файл.** Создал `secret.txt` с учебным паролем. `ls -l` показал права `-rw-r--r--` (644): новые файлы по умолчанию может читать ЛЮБОЙ пользователь системы. Закрыл файл командой `chmod 600 secret.txt` → стало `-rw-------`: читать и изменять может только владелец (и root, который игнорирует права). Вывод: файлы с паролями, ключами, токенами (например, `.env`) нужно закрывать сразу после создания — сами по себе они не защищены.

- **Общая папка для группы.** Задача: две учётные записи (vetal и testuser) должны работать в одной папке, а остальные — ничего не видеть. Создал группу `webteam`, добавил в неё обоих (`usermod -aG`), создал `/srv/webteam` с владельцем `root:webteam` и правами `770`.
  - Проблема 1: после добавления в группу у vetal всё равно не было доступа. Причина — группы загружаются при входе в систему. Решение: перезайти (`su - vetal`).
  - Проблема 2: vetal не мог дописать в файл, созданный testuser. `ls -l` показал, что файл получил группу создателя (`testuser`), а не группу папки → для vetal действовала третья тройка `r--`. Решение: включил на папке setgid (`chmod g+s`) — новые файлы стали получать группу `webteam`; старый файл исправил через `chgrp webteam`.
  - В конце удалил учебного пользователя, группу и папку.
  - Вывод: для совместной работы права выдают через группу; для общих папок нужен setgid; после изменения групп нужен перевход.
