# Занятие 9. Журналы: journalctl

## Главное своими словами
systemd-journald собирает в одно место сообщения всех служб и ядра. journalctl позволяет выбрать нужное: по службе, по времени, по важности, по загрузке. Это основной инструмент, чтобы понять, что происходило с сервером в прошлом.

## Выборка
- По службе: -u; по времени: --since / --until; последние строки: -n; в реальном времени: -f
- По важности: -p err — ошибки и серьёзнее; echo службы имеет уровень info
- По загрузке: -b — текущая, -b -1 — предыдущая, --list-boots — все
- По тексту: -g или grep; по метке: -t

## Время
- Журнал показывает время по поясу системы; -o short-iso добавляет смещение, --utc показывает UTC
- При разборе инцидента сначала выяснить часовой пояс каждого источника

## Размер
- --disk-usage — сколько занято; --vacuum-size / --vacuum-time — очистка
- Очистка удаляет историю навсегда; постоянный предел — в journald.conf

## Как читать записи
- Started — процесс запущен, но не обязательно работает
- Failed to start — итог после всех попыток
- -p err показывает факт ошибки, причина часто в строках с более низким уровнем
- У системы есть фоновый шум безвредных ошибок — его нужно знать

## Что я сделал на практике
- **Расследование аварии heartbeat.** Зная примерное время, выбрал записи за промежуток: `journalctl -u heartbeat --since "2026-11-10 16:25" --until "2026-11-10 16:35" --no-pager`. Нашёл точное время (16:29:56), причину (`status=203/EXEC` — опечатка в ExecStart) и 5 попыток перезапуска, после которых systemd сдался. Служба не работала около двух минут.
- **Исправление User=nobody.** В журнале нашёл предупреждение `Special user nobody configured, this is not safe!` — в `systemctl status` его не было видно. Заменил в юните `User=nobody` на `DynamicUser=yes`: правка в репозитории → копия в систему → daemon-reload → проверка → коммит.
- **Очистка журнала.** `--vacuum-size=200M` освободил 271,8 МБ, но удалил историю двух самых старых загрузок из 12 — восстановить её нельзя.
- **Справка по службе.** Посчитал строки `Started` (12) и решил, что неудачный запуск был один. Ошибся: 5 из них — неудачные попытки, после каждой шло `203/EXEC`. Правильно: 7 успешных запусков и 5 неудачных. Вывод: Started — процесс запущен, но не обязательно работает; смотреть следующие строки.

## Что стало открытием
- Журнал хранит записи до предела размера; сколько загрузок он помнит, зависит от этого предела
- Started значит «процесс запущен», а не «служба работает»
- Время системы и время в разных журналах может быть в разных часовых поясах — сначала это проверять
- Некоторые предупреждения видны только в журнале, а не в systemctl status
