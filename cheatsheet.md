# Шпаргалка

## Где что лежит на Linux-сервере
| Что ищу | Где | Аналог в Windows |
|---|---|---|
| Установленные программы | `/usr` (`/usr/bin`, `/usr/sbin`) | `C:\Program Files` |
| Настройки программ | `/etc` (например, `/etc/nginx/`) | «Настройки» программ |
| Файлы сайтов | `/var/www` | «Мои документы» — мои данные |
| Логи | `/var/log` (например, `/var/log/nginx/`) | Журнал событий |
| Домашние папки пользователей | `/home/имя` | `C:\Users\имя` |
| Папка администратора root | `/root` | папка администратора |
| Временные файлы | `/tmp` | `C:\Windows\Temp` |
| Информация о системе «прямо сейчас» | `/proc` (виртуальная) | Диспетчер задач |
| Диск C: Windows (из WSL) | `/mnt/c` | — |
| Пользователи (логин, UID, домашняя папка, оболочка) | `/etc/passwd` | — |
| Хэши паролей (только root) | `/etc/shadow` | — |
| Группы и их участники | `/etc/group` | — |
| Шаблон домашней папки нового пользователя | `/etc/skel` | — |
| Лог входов и использования sudo | `/var/log/auth.log` | Журнал безопасности |
| Данные, которые обслуживает сервер | `/srv` | — |

Программа — в `/usr`, её настройки — в `/etc`, сайт, который она показывает, — в `/var/www`, её логи — в `/var/log`.

## Навигация
| Команда | Что делает | Пример |
|---|---|---|
| `pwd` | показать, где я сейчас | `pwd` |
| `cd путь` | перейти в папку | `cd /var/log` |
| `cd ..` | на уровень выше | `cd ..` |
| `cd ~` или `cd` | домой (`/home/vetal`) | `cd ~` |
| `cd -` | вернуться в предыдущую папку | `cd -` |
| `ls` | список файлов | `ls` |
| `ls -l` | подробный список (права, владелец, размер) | `ls -l /etc` |
| `ls -a` | показать скрытые файлы (с точкой в начале) | `ls -a ~` |
| `ls -lah` | всё сразу, размеры понятные (K, M, G) | `ls -lah` |
| `ls -lhS` | сортировка по размеру, большие сверху | `ls -lhS /var/log` |
| `ls -ld папка` | права самой папки, а не содержимого | `ls -ld /root` |
| `tree` | структура папок деревом | `tree` |

Обозначения: `.` — текущая папка, `..` — родительская, `~` — домашняя, `/` — корень.

|---|---|

## Поиск файлов
Шаблон: `find ГДЕ_ИСКАТЬ УСЛОВИЕ`

| Пример | Что найдёт |
|---|---|
| `find ~/devops-learning -name "*.md"` | все файлы `.md` в репозитории |
| `find /etc -name "*.conf"` | все файлы, оканчивающиеся на `.conf` |
| `find ~ -name "app.conf"` | файл с точным именем |
| `find ~ -type f -name "*.log"` | только файлы (`f` — file) |
| `find ~ -type d -name "notes"` | только папки (`d` — directory) |
| `find /var/log -size +100k` | файлы больше 100 КБ |
| `find / -size +100M` | файлы больше 100 МБ (когда кончается место) |
| `sudo find /etc -name "*.key"` | поиск и в закрытых папках |

- `*` — любые символы; шаблон со звёздочкой ВСЕГДА в кавычках: `"*.conf"`
- Размеры: `k` — маленькая, `M` и `G` — большие (`+100K` — ошибка!)
- find заходит и в скрытые папки → указывать место поиска как можно точнее
- `Permission denied` в find — не авария: find сообщает и продолжает искать
- `ls` смотрит в одну папку, `find` — во все вложенные

## Пользователи и группы
| Команда | Что делает |
|---|---|
| `whoami` | моё имя |
| `id` | мой UID, GID и группы (текущей сессии) |
| `id имя` | UID, GID и группы пользователя (актуальные данные) |
| `groups` | список моих групп |
| `sudo adduser имя` | создать пользователя (папка, пароль — всё сразу) |
| `su - имя` | войти под другим пользователем (нужен ЕГО пароль) |
| `exit` | вернуться обратно |
| `sudo deluser --remove-home имя` | удалить пользователя и его папку |
| `sudo groupadd имя` | создать группу |
| `sudo groupdel имя` | удалить группу |
| `sudo usermod -aG группа имя` | добавить пользователя в группу |

- ВСЕГДА `-aG`! Без `-a` пользователь потеряет все остальные группы (и `sudo`)
- Новые группы применяются только после нового входа (`su - имя` или перезайти по SSH)
- Строка `/etc/passwd`: `логин:x:UID:GID:комментарий:домашняя_папка:оболочка`
- Строка `/etc/group`: `имя:x:GID:участники`
- UID 0 — root; UID < 1000 — служебные; UID ≥ 1000 — люди
- `/usr/sbin/nologin` — войти под этим пользователем нельзя (служебный)

## Права доступа
Строка прав: `-rwxr-xr--` = тип + владелец (u) + группа (g) + остальные (o)

| Буква | Файл | Папка |
|---|---|---|
| `r` (4) | читать | видеть список имён |
| `w` (2) | изменять | создавать, удалять, переименовывать файлы внутри |
| `x` (1) | запускать | входить (`cd`) |

Разбор `Permission denied`:
1. `ls -l файл` / `ls -ld папка` — владелец, группа, права
2. `id` — кто я, мои группы
3. Моя тройка: владелец? → 1-я; в группе файла? → 2-я; иначе → 3-я (срабатывает ОДНА)
4. Есть ли нужная буква в моей тройке?
5. Проверить папку: `x` — войти, `w` — создать/удалить

| Число | Буквы | Где |
|---|---|---|
| `644` | `rw-r--r--` | обычные файлы, конфиги |
| `600` | `rw-------` | секреты, приватные ключи |
| `755` | `rwxr-xr-x` | папки, скрипты, программы |
| `700` | `rwx------` | личные папки (`~/.ssh`) |
| `770` | `rwxrwx---` | общая папка группы |

| Команда | Что делает |
|---|---|
| `chmod u+x файл` | владельцу добавить запуск |
| `chmod o-r файл` | остальным убрать чтение |
| `chmod 600 файл` | установить права цифрами |
| `chmod -R 755 папка` | рекурсивно (осторожно!) |
| `sudo chown владелец:группа файл` | сменить владельца и группу |
| `sudo chown -R www-data:www-data /var/www/site` | отдать сайт веб-серверу |
| `sudo chgrp группа файл` | сменить только группу |
| `sudo chmod g+s папка` | setgid: новые файлы получат группу папки |
| `./файл` | запустить файл из текущей папки |

- Права НЕ наследуются: папка — это дверь, у каждого файла свои права
- root игнорирует права
- Новые файлы по умолчанию читаются всеми → секреты сразу `chmod 600`
- НИКОГДА `chmod 777`
- `t` (sticky bit, на `/tmp`) — удалять можно только свои файлы
- `s` в тройке группы — setgid
- Первая строка скрипта: `#!/bin/bash` (shebang)
- Каждый `sudo` записывается в `/var/log/auth.log`
- Пустой вывод команды = успех («молчание — знак успеха»)

## Потоки и перенаправление
| Поток | № | Что это |
|---|---|---|
| stdin | 0 | ввод (клавиатура или файл) |
| stdout | 1 | обычный вывод |
| stderr | 2 | ошибки |

| Запись | Что делает |
|---|---|
| `команда > файл` | вывод в файл (ПЕРЕЗАПИСЫВАЕТ молча!) |
| `команда >> файл` | дописать в конец файла |
| `команда 2> файл` | ошибки в файл |
| `команда 2>/dev/null` | ошибки выбросить |
| `команда > файл 2>&1` | вывод и ошибки в один файл |

- `>` — для свежих отчётов, `>>` — для логов (накопление). Повторный `>>` дублирует данные
- `/dev/null` — «чёрная дыра»
- Команда без файла ждёт ввода с клавиатуры → `Ctrl+C`

## Конвейер и обработка текста
`команда1 | команда2` — вывод левой становится вводом правой (передаётся только stdout, НЕ файл)

| Команда | Что делает |
|---|---|
| `grep "текст" файл` | строки, где есть текст |
| `grep -i` | без учёта регистра |
| `grep -v` | строки, где текста НЕТ |
| `grep -c` | количество строк |
| `grep -n` | с номерами строк |
| `grep -r "текст" папка` | искать во всех файлах папки |
| `cut -d ':' -f 7 файл` | вырезать 7-ю колонку, разделитель `:` |
| `sort` / `sort -n` / `sort -nr` | по алфавиту / как числа / от большего |
| `uniq` / `uniq -c` | склеить СОСЕДНИЕ повторы / и посчитать (нужен `sort` перед ним!) |
| `awk '{print $1}' файл` | 1-я колонка (разделитель — пробелы, любое количество) |
| `awk '{print $1, $7}'` | несколько колонок |
| `awk '{print $NF}'` | последняя колонка |
| `awk -F ':' '{print $7}'` | другой разделитель |
| `awk '$9 == 404' файл` | строки по условию |
| `awk '$9 == 500 {print $7}' файл` | условие + колонка |
| `printf "a\nb\n" > файл` | записать несколько строк (`\n` — новая строка) |

**Рецепт «топ самых частых»:**
`... | sort | uniq -c | sort -nr | head`

**Примеры:**
- топ IP: `awk '{print $1}' access.log | sort | uniq -c | sort -nr | head`
- топ кодов ответа: `awk '{print $9}' access.log | sort | uniq -c | sort -nr`
- страницы с ошибкой 500: `awk '$9 == 500 {print $7}' access.log | sort | uniq -c | sort -nr`
- число конфигов: `find /etc -name "*.conf" 2>/dev/null | wc -l`
- Числа — БЕЗ кавычек (`$2 > 30`), текст — В кавычках (`$3 == "Киев"`). `"30"` в кавычках = сравнение как текст (по символам, как в словаре) — ошибка на числах
- Сравнение — `==` (один `=` — это присваивание)
- Запятая в `print` сама ставит пробел: `print $1, "получает", $4`
- `$0` — вся строка, `$NF` — последнее поле
- Условия: `==`, `!=`, `>`, `>=`, `<`, `<=`; «и» — `&&`
- Пример: имена людей (без nobody): `awk -F ':' '$3 >= 1000 && $3 < 65534 {print $1}' /etc/passwd`
- Огромный вывод → сначала `| head`.

## Лог веб-сервера (Nginx/Apache)
`IP - - [дата] "МЕТОД /страница HTTP/1.1" КОД РАЗМЕР "откуда" "программа"`
- `$1` — IP, `$4` — время, `$7` — страница, `$9` — код ответа, `$10` — размер
- Коды: `200` — успех, `301` — переадресация, `404` — не найдено, `500` — ошибка сервера
- access.log — ЧТО произошло; error.log — ПОЧЕМУ сломалось

## Архивы и сжатие
| Команда | Что делает |
|---|---|
| `tar -czf архив.tar.gz папка` | упаковать и сжать |
| `tar -czf архив.tar.gz -C /путь папка` | упаковать папку из указанного места (короткие пути в архиве) |
| `tar -tzf архив.tar.gz` | посмотреть содержимое, не распаковывая |
| `tar -xzf архив.tar.gz` | распаковать в текущую папку (перезаписывает молча!) |
| `tar -xzf архив.tar.gz -C папка/` | распаковать в указанную папку |
| `gzip файл` | сжать → файл.gz (ОРИГИНАЛ ИСЧЕЗАЕТ) |
| `gunzip файл.gz` | разжать |
| `zcat файл.gz` | прочитать сжатый файл без распаковки |

- Флаги tar: `c` — создать, `t` — список, `x` — извлечь, `z` — gzip, `f` — имя архива (ВСЕГДА последний), `v` — подробно
- `.tar` — коробка, `.gz` — сжатие, `.tar.gz` — сжатая коробка
- tar сохраняет права, владельца и даты файлов
- Перед распаковкой: `tar -t` (что внутри) и `pwd` (куда распаковываю)
- Бэкап без проверки восстановления — не бэкап
- Бэкап с датой: `tar -czf backup-$(date +%F).tar.gz -C $HOME/sandbox server`

## Переменные окружения
| Команда | Что делает |
|---|---|
| `ИМЯ="значение"` | создать переменную (БЕЗ пробелов вокруг `=`) |
| `echo $ИМЯ` | показать значение |
| `export ИМЯ` | сделать переменной окружения (её получат дочерние программы) |
| `export ИМЯ="значение"` | создать и экспортировать сразу |
| `printenv` / `env` | все переменные окружения |
| `$(команда)` | подставить результат команды: `echo "Сегодня $(date +%F)"` |
| `source ~/.bashrc` | перечитать настройки в текущем терминале |
| `history` | история команд |

- Готовые: `$HOME`, `$USER`, `$PWD`, `$OLDPWD` (для `cd -`), `$SHELL`, `$PATH`
- `"$HOME"` — подставит значение; `'$HOME'` — оставит текст как есть
- Опечатка в имени переменной = пустая строка БЕЗ ошибки (опасно: `rm -rf $ОПЕЧАТКА/`)
- Переменные живут до закрытия терминала; постоянные — в `~/.bashrc`
- Правка `~/.bashrc`: сначала `cp ~/.bashrc ~/.bashrc.bak`, дописывать только `>>`
- Дочерняя программа получает КОПИЮ окружения и не может изменить переменные родителя
- Пароли не вводить в командах — они остаются в history и видны в списке процессов

## PATH и поиск команд
| Команда | Что показывает |
|---|---|
| `echo $PATH \| tr ':' '\n'` | список папок, где ищутся команды, по строке |
| `which команда` | где лежит файл программы |
| `type команда` | что это: программа, встроенная команда или псевдоним |

- Bash ищет команду по папкам PATH по порядку, запускает ПЕРВУЮ найденную
- Текущей папки нет в PATH (защита от подложенных программ) → `./скрипт`
- Своя команда: файл в `~/bin` + `export PATH="$HOME/bin:$PATH"` в `~/.bashrc`
- НИКОГДА не писать `PATH="папка"` без `:$PATH` — сломаются все команды
- `command not found` после установки → `which`, `echo $PATH`
- `cd`, `export`, `source` — встроенные (меняют текущий терминал, поэтому не могут быть отдельными программами)
- `ll` = `ls -alF` (псевдоним), `ls` = `ls --color=auto`
- В WSL в PATH добавлены папки Windows (поэтому работает `code .`)

## Процессы
| Команда | Что делает |
|---|---|
| `ps` | процессы этого терминала |
| `ps aux` | все процессы подробно |
| `ps -ef` | все процессы с PPID (родителем) |
| `ps -o pid,ppid,cmd` | только нужные колонки |
| `ps aux --sort=-%mem \| head` | кто больше всех ест память |
| `pgrep -a имя` | найти процесс по имени (без строки самого grep) |
| `echo $$` | PID текущего терминала |
| `cat /proc/PID/status` | информация о процессе |

- Процесс = запущенная программа; PID — номер, PPID — номер РОДИТЕЛЯ, USER — от чьего имени (права как у пользователя)
- Цепочка родителей всегда ведёт к PID 1
- ps aux: %CPU, %MEM, RSS (память в КБ), STAT (R — работает, S — спит, Z — зомби)
- `ps aux | grep имя` показывает и сам grep — не пугаться
- Убрать заголовок: `| tail -n +2`
- Аргументы команд видны всем в `ps aux` → секреты не передавать в командной строке

## Мониторинг: top и htop
- `nproc` — число ядер; `uptime` — время работы и load average
- Load average: за 1, 5, 15 минут; сравнивать с числом ядер (меньше — норма, больше — очередь)
- Первое число больше последнего — нагрузка растёт, меньше — спадает
- %CPU считается на ОДНО ядро; многопоточная программа может показать больше 100% (до 100% × ядра)
- %Cpu: us — программы, sy — ядро, id — простой, wa — ожидание диска
- Память: смотреть `avail Mem`, а не free (buff/cache — кэш, освобождается сам)
- Активный swap — памяти не хватает, система тормозит
- top: `P` — по CPU, `M` — по памяти, `1` — ядра отдельно, `q` — выход
- htop: `F5` — дерево, `F6` — сортировка, `F4` — фильтр, `F10` — выход
- На серверах htop может не быть — уметь читать top

## ⚡ «Сервер тормозит» — 3 ресурса
| Ресурс | Где в top | Проблема |
|---|---|---|
| Процессор | load average + `nproc` | нагрузка больше числа ядер |
| Память | avail Mem, Swap | мало available, swap используется |
| Диск | `wa` в строке %Cpu | высокий wa |

## Управление процессами
| Команда | Что делает |
|---|---|
| `kill PID` | вежливо завершить (SIGTERM, 15) |
| `kill -9 PID` | убить немедленно (SIGKILL) — последнее средство |
| `pkill имя` | завершить все процессы с этим именем |
| `команда &` | запустить в фоне |
| `jobs` / `jobs -l` | фоновые задачи (с PID) |
| `Ctrl+Z` | пауза |
| `bg` / `fg` | продолжить в фоне / вернуть на передний план |
| `kill %1` | завершить задачу по номеру из jobs |
| `nice -n 19 команда` | запустить с низким приоритетом |

- Правило: сначала `kill`, подождать, только потом `kill -9`
- SIGTERM программа может перехватить или игнорировать; SIGKILL выполняет ядро — игнорировать нельзя
- `kill` понимает только номера, `pkill` — имена
- Завершать можно только СВОИ процессы (чужие — sudo)
- НИКОГДА `sudo kill 1`
- nice от -20 до 19, больше = вежливее; nice — не ограничение, а очередь (уступает только при конкуренции)
- Фоновые задачи умирают с терминалом; постоянные программы — службы systemd (Модуль 2)

## Диски и память
| Команда | Что показывает |
|---|---|
| `free -h` | оперативная память (смотреть available) |
| `df -h` | заполненность дисков (главное — Use%) |
| `df -h / /mnt/c` | только нужные разделы |
| `du -sh папка` | размер папки |
| `du -h --max-depth=1 папка \| sort -h` | размер подпапок, по возрастанию |
| `sudo find / -xdev -type f -size +100M 2>/dev/null` | большие файлы на этом диске |
| `find ... -exec ls -lh {} \;` | показать размер каждого найденного файла |
| `fallocate -l 300M файл` | быстро создать файл нужного размера (для тестов) |

**Алгоритм «кончилось место»:**
1. `df -h` — какой раздел заполнен
2. `sudo du -h --max-depth=1 / 2>/dev/null | sort -h` — самая большая папка
3. Спускаться в самую большую и повторять du
4. `sudo find / -xdev -type f -size +100M` — крупные файлы
5. Перед удалением — понять, что это за файл!

- `sort -h` понимает K, M, G (`sort -n` — нет)
- du находит папки с МНОЖЕСТВОМ мелких файлов, find -size — ОДИН большой файл → использовать оба
- `-xdev` — не уходить на другие диски
- Use% 100% у раздела только для чтения — норма; тревожно для разделов, куда пишут данные
- Частые виновники: /var/log (журнал systemd), бэкапы, Docker, кэш apt (`sudo apt clean`)

## Bash-скрипты
### Основа
- Первая строка: `#!/bin/bash`; комментарии: `#`
- В начале скрипта: `set -euo pipefail`
  - `-e` — остановиться при ошибке команды (НЕ срабатывает внутри условия if!)
  - `-u` — ошибка при несуществующей переменной (защита от опечаток)
  - `-o pipefail` — конвейер падает, если упала любая его часть
- Запуск: `bash script.sh` или `chmod +x` + `./script.sh`
- Переменные в скриптах — ВСЕГДА в кавычках: `"$VAR"` (иначе пробелы разрежут значение)
- `$(команда)` — подставить результат
- `${1:-80}` — аргумент или значение по умолчанию

### Аргументы
| Переменная | Значение |
|---|---|
| `$1`, `$2` | аргументы скрипта (внутри функции — аргументы функции) |
| `$#` | количество аргументов |
| `$0` | имя скрипта |
| `$?` | код возврата ПОСЛЕДНЕЙ команды |

### Код возврата
- `0` — успех, не 0 — ошибка или «нет»
- grep: 0 — нашёл, 1 — не нашёл, 2 — ошибка (коды программ — в `man`, раздел EXIT STATUS)
- `exit N` — выйти из скрипта с кодом N; `return N` — из функции
- Описывать коды в комментарии в начале скрипта

### Условия
```bash
if [ условие ]; then
    ...
elif [ условие ]; then
    ...
else
    ...
fi
```
| Проверка | Значение |
|---|---|
| `-f` / `-d` / `-e` | файл / папка / существует |
| `-z "$V"` | переменная пустая |
| `!` | отрицание: `[ ! -d "$D" ]` |
| `"$A" = "$B"` | строки равны |
| `-eq -ne -gt -lt -ge -le` | числа: =, ≠, >, <, ≥, ≤ |
| `[[ "$V" =~ ^[0-9]+$ ]]` | значение — число |

- Пробелы внутри `[ ]` обязательны (`[` — это команда)
- Числа сравнивать `-gt`, а не `>` (`>` — перенаправление!)
- `if команда` проверяет код возврата команды: `if grep -q "текст" файл; then`
- `кмд1 && кмд2` — кмд2, если кмд1 успешна; `кмд1 || кмд2` — если не удалась

### Циклы
```bash
for X in a b c; do echo "$X"; done
for i in {1..5}; do echo "$i"; done
for f in /путь/*.log; do echo "$f"; done
while read -r line; do echo "$line"; done < файл
```
- `continue` — перейти к следующему кругу
- `$((A + 1))` — арифметика
- `wc -l < файл` — только число строк

### Функции
```bash
name() {
    local X="$1"      # local — переменная только внутри функции
    ...
    return 0
}
name "аргумент"
```

### Полезное
- `basename /a/b/c` → `c`; `dirname /a/b/c` → `/a/b`
- `df -P` — стабильный формат df для скриптов; `tr -d '%'` — удалить символ
- `команда | tee -a журнал.log` — и на экран, и в файл
- `find папка -name "*.tar.gz" -mtime +7 -print -delete` — удалить старше 7 дней (сначала проверить БЕЗ -delete!)
- `date '+%F %T'` — дата и время; `date +%F_%H%M` — для имён файлов
- `git diff` — что изменилось до `git add`; `git diff --staged` — после
- `git rm файл` — удалить файл и сообщить Git

### Многострочные команды в терминале
- Можно нажимать Enter: Bash покажет `>` и будет ждать `done`/`fi`; Ctrl+C — отменить
- Одной строкой: `;` там, где был бы перенос: `if [ -d x ]; then echo да; else echo нет; fi`
- `\` в конце строки — продолжение длинной команды
- ↑ показывает многострочную команду одной строкой
- Больше 3 строк — писать в файл-скрипт

### Главное правило проверок
Испытать проверку на случае, когда она ОБЯЗАНА сработать (порог 1%). Сломанная проверка может молча говорить «всё OK».

## systemd и службы
- Служба (демон) — программа, работающая постоянно в фоне без терминала; управляет ими systemd (PID 1)
- Юниты: `/usr/lib/systemd/system/` — от пакетов (не править), `/etc/systemd/system/` — свои
- Свои программы — в `/usr/local/bin/`

| Команда | Что делает |
|---|---|
| `systemctl status имя` | состояние службы + последние строки журнала |
| `systemctl --failed` | упавшие службы (первая команда при проблемах) |
| `systemctl list-units --type=service --state=running` | работающие службы |
| `systemctl is-active [--quiet] имя` | работает ли (код: 0 — да, 3 — нет, 4 — нет такой службы) |
| `systemctl is-enabled имя` | включён ли автозапуск |
| `systemctl cat имя` | показать файл юнита |
| `sudo systemctl start / stop / restart имя` | запустить / остановить / перезапустить |
| `sudo systemctl reload имя` | перечитать конфиг без остановки (если есть ExecReload) |
| `sudo systemctl enable / disable имя` | включить / выключить автозапуск |
| `sudo systemctl enable --now имя` | автозапуск + запустить сразу |
| `sudo systemctl daemon-reload` | перечитать файлы юнитов (ПОСЛЕ КАЖДОЙ ПРАВКИ ЮНИТА!) |
| `journalctl -u имя` / `-f` | журнал службы / в реальном времени |

- `active` — работает СЕЙЧАС; `enabled` — запустится ПРИ ЗАГРУЗКЕ (независимы!)
- `enable` = символическая ссылка в `/etc/systemd/system/multi-user.target.wants/`
- `stop` отправляет SIGTERM; осознанная остановка не перезапускается, авария (kill -9) — перезапускается при `Restart=on-failure`
- После нескольких быстрых падений подряд systemd сдаётся: `Start request repeated too quickly` → failed
- restart — с перерывом в работе; reload — без перерыва (для Nginx после правки конфига — reload)
- Опасно останавливать: ssh, сеть, базы данных
- Точка в status: ● зелёная — работает, ○ — остановлена, × красная — ошибка
- Без daemon-reload служба работает по СТАРОЙ версии юнита → сломается при следующей загрузке
- `status=203/EXEC` — systemd не смог запустить программу из ExecStart (нет файла / нет права x)
- Из less выходить `q`, а не Ctrl+Z (иначе процесс на паузе, STAT = T)

### Шаблон юнита
```ini
[Unit]
Description=Описание службы
After=network.target

[Service]
ExecStart=/usr/local/bin/программа
Restart=on-failure
User=nobody

[Install]
WantedBy=multi-user.target
```
- `ExecStart` — команда запуска; `Restart=on-failure` — поднимать после аварии
- `User=` — от кого работает (по умолчанию root!); `After=` — порядок запуска
- `WantedBy=multi-user.target` — запускать при обычной загрузке
- Вывод службы (echo) автоматически попадает в журнал

### Порядок: своя служба
1. Скрипт и юнит — в репозитории (источник правды — Git)
2. `sudo cp` скрипт в `/usr/local/bin/`, `chmod 755`
3. `sudo cp` юнит в `/etc/systemd/system/`
4. `sudo systemctl daemon-reload`
5. `sudo systemctl enable --now имя`
6. `systemctl status имя`, `journalctl -u имя`

## Журнал: journalctl
| Команда | Что показывает |
|---|---|
| `journalctl -u имя` | журнал одной службы |
| `journalctl -n 20` / `-e` / `-r` | последние 20 / открыть в конце / новые сверху |
| `journalctl -f` | в реальном времени |
| `journalctl --since "10 min ago"` | за последние 10 минут |
| `journalctl --since today` / `yesterday` | с начала дня |
| `journalctl --since "2026-11-10 16:25" --until "2026-11-10 16:35"` | за промежуток |
| `journalctl -p err` | ошибки и серьёзнее (`warning` — с предупреждениями) |
| `journalctl -b` / `-b -1` | текущая / предыдущая загрузка |
| `journalctl --list-boots` | список загрузок |
| `journalctl -g "текст"` | поиск по тексту |
| `journalctl -t метка` | записи с меткой (от logger) |
| `journalctl -o short-iso` / `--utc` | время со смещением / в UTC |
| `journalctl --disk-usage` | размер журнала |
| `sudo journalctl --vacuum-size=200M` | удалить старое, оставить 200 МБ |
| `sudo journalctl --vacuum-time=2weeks` | удалить старше двух недель |
| `logger -t метка [-p user.err] "текст"` | своя запись в журнал |
| `timedatectl` | время и часовой пояс системы |
| `--no-pager` | вывести без less |

- Уровни: 0–2 критические, 3 err, 4 warning, 5 notice, 6 info, 7 debug; `-p` показывает этот уровень и серьёзнее
- `echo` службы — уровень info; `-p err` его не покажет
- Порядок разбора: `-p err` → факт и время ошибки → весь журнал вокруг этого времени → причина
- `-- Boot ... --` — граница между загрузками
- `Started` = процесс запущен, НЕ значит «работает»; смотреть следующие строки
- `Failed to start` — итог, а не каждая попытка
- Опечатка в имени службы → пустой вывод без ошибки
- Очистка журнала удаляет историю безвозвратно; предел — `SystemMaxUse=` в `/etc/systemd/journald.conf`
- Чтение журнала без sudo — через группу adm
- При разборе инцидента сначала выяснить часовой пояс каждого источника
- В WSL постоянный «шум»: kernel dxg/PCI, pam_lastlog, getaddrinfo — безвредно
- `DynamicUser=yes` — отдельный временный пользователь для службы (лучше, чем User=nobody)

## Порты и сокеты
- IP — адрес здания, порт — номер кабинета (1–65535), сокет — адрес:порт, открытый программой
- Порты ниже 1024 открывает только root; выше — любой пользователь; порт 0 — «дай любой свободный»

| Порт | Служба |
|---|---|
| 22 | SSH |
| 53 | DNS |
| 80 / 443 | HTTP / HTTPS |
| 3306 / 5432 | MySQL / PostgreSQL |
| 9000 | PHP-FPM (часто) |

| Адрес в ss | Значение |
|---|---|
| `127.0.0.1:порт` | только изнутри (localhost) |
| `0.0.0.0:порт`, `*:порт` | на всех интерфейсах — доступно снаружи |
| `[::]:порт` | все адреса IPv6 |
| `127.0.0.53%lo:53` | привязано к интерфейсу lo (loopback) |

- Доступ снаружи определяет АДРЕС, а не номер порта
- База данных должна слушать 127.0.0.1, а не 0.0.0.0
- Один порт на одном адресе — только одна программа (`Address already in use`)

| Команда | Что делает |
|---|---|
| `sudo ss -tlnp` | TCP, слушающие, числами, с процессом |
| `sudo ss -tulnp` | + UDP |
| `grep -w "22/tcp" /etc/services` | имя порта |
| `hostname -I` | сетевой адрес машины |
| `python3 -m http.server 8000 [--bind 127.0.0.1] [--directory папка]` | учебный веб-сервер |

## curl
| Команда | Что делает |
|---|---|
| `curl http://адрес:порт` | получить страницу |
| `curl -I http://...` | только заголовки |
| `curl -v http://...` | подробно |
| `curl -s -o /dev/null -w "%{http_code}\n" http://...` | только код HTTP |
| `curl -f http://...` | ненулевой код возврата (22) при HTTP 400 и выше |

- `Connection refused` / `Couldn't connect` (код 7) — никто не слушает на этом адресе и порту
- `Connection timed out` — нет ответа, обычно файрвол
- curl возвращает 0 даже при HTTP 404! Для проверок — `-w "%{http_code}"` или `-f`
- Время в HTTP-заголовках всегда в GMT

## Диагностика «служба работает, а сайт не открывается»
1. `systemctl status имя` — работает? ошибки?
2. `journalctl -u имя -n 50` — что писала?
3. `sudo ss -tlnp` — слушает? какой порт? какой адрес?
4. `curl -I http://127.0.0.1:порт` — отвечает изнутри? код?
5. `curl -I http://СЕТЕВОЙ_АДРЕС:порт` — отвечает снаружи?
6. Файрвол, DNS

- status и журнал могут говорить «всё хорошо», правду показывает ss
- После правки юнита: cp → daemon-reload → **restart** → проверка (daemon-reload и enable --now работающий процесс не перезапускают)
- Python traceback — читать последнюю строку
- `sudo tee файл` — записать в файл, куда нет прав: `echo "текст" | sudo tee файл`
- Данные служб — в `/srv`

## cron
`мин час день месяц день_недели команда`

| `*/5 * * * *` | каждые 5 минут |

| Команда | Что делает |

| `crontab -l` | показать |
| `sudo crontab -e` | расписание root |

- Системное: `/etc/crontab`, `/etc/cron.d/`, `/etc/cron.hourly`, `/etc/cron.daily`
- В crontab ТОЛЬКО полные пути: cron не читает ~/.bashrc, PATH короткий
- Вывод теряется (`No MTA installed, discarding output`) → писать в журнал через logger или `>> файл 2>&1`
- `%` в crontab — особый символ (`\%`)
- Проверка расписания: crontab.guru

## Таймеры systemd
- Два файла: `имя.service` (что делать, `Type=oneshot`, без `[Install]`) + `имя.timer` (когда)

```ini
# имя.timer
[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

| OnCalendar | Когда |
|---|---|
| `*:0/1` | каждую минуту |
| `*:0/5` | каждые 5 минут |
| `hourly` / `daily` | каждый час / в полночь |
| `*-*-* 03:00:00` | каждый день в 03:00 |
| `Mon..Fri 08:30` | по будням в 08:30 |

| Команда | Что делает |
|---|---|
| `systemd-analyze calendar "расписание"` | проверить расписание, Next elapse |
| `sudo systemctl enable --now имя.timer` | включить ТАЙМЕР (не службу!) |
| `systemctl list-timers` | все таймеры: последний и следующий запуск |
| `sudo systemctl start имя.service` | выполнить задание вручную |
| `journalctl -u имя.service` | вывод задания |

- `Persistent=true` — выполнить пропущенный запуск при включении (для бэкапов; для частых проверок не нужен)
- Служба для таймера — `static` (без [Install]); включается таймер
- oneshot: `inactive (dead)` после работы — норма; ненулевой код → `failed` → видно в `--failed`
- oneshot не нужно перезапускать после правки юнита: каждый запуск — новый процесс
- Заданию нужны файлы пользователя → `User=имя`; не нужны → `DynamicUser=yes`; не root «на всякий случай»
- `start` без `enable` — таймер не переживёт перезагрузку!
- Системные таймеры: logrotate, apt-daily, dpkg-db-backup

## cron или таймер
| | cron | таймер |
|---|---|---|
| Простота | одна строка | два файла |
| Вывод | теряется | в журнале |
| Пропущенный запуск | теряется | Persistent=true |
| Ошибка | никто не узнает | --failed |

- Точность мониторинга = интервал проверки (раз в минуту → ±1 минута)
- `|| true` после команды в скрипте с set -e — чтобы ожидаемая ошибка не остановила скрипт
